= bestikk-changelog Changelog
:uri-repo: https://github.com/bestikk/bestikk-changelog

This document provides a high-level view of the changes introduced in bestikk-changelog by release.
For a detailed view of what has changed, refer to the {uri-repo}/commits/main[commit history] on GitHub.

== Unreleased

=== Fixed

* Fix the `title-paren-suffix` style swallowing the first line of a release's summary paragraph when the release heading has no suffix
* Forward the `suffix` option to the heading template for the `adoc` format too (it was silently ignored, e.g. with `--style title-paren-suffix --suffix "- @octocat"`)
* Keep `$` patterns (e.g. `$&`) verbatim in the release heading written by `release`, instead of interpreting them as `String.prototype.replace()` replacement patterns
* Reject a CLI option missing its value (e.g. a trailing `--file`, or `--file --format md`) with the usage, instead of crashing with a stack trace or silently ignoring it (`--date` fell back to today)
* Report CLI errors (e.g. changelog file or section not found) as a one-line message with exit code `1`, instead of an uncaught exception's stack trace
* Ignore `##`/`###` lines inside fenced code blocks (including AsciiDoc source/literal blocks) when looking for the release section and its categories; such a line used to cut the release notes short
* Omit the "Summary" (or "Changelog") section from the release notes when the release has no summary paragraph (or no category section), instead of rendering an empty section
* Refuse to `release` a version that already has a release section, instead of adding a duplicate one
* Accept a `v`-prefixed version (e.g. `release v1.0.0`), which used to produce a heading such as `== vv1.0.0 (...)`
* Support CRLF line endings: `notes` failed to find the release section with the `title-paren`/`title-paren-suffix` styles (and kept a trailing `\r` in the date with `keepachangelog`), and `release` inserted LF line endings into a CRLF file

=== Changed

* Parse CLI arguments with `node:util`'s `parseArgs()`: options now also accept the `--option=value` form and can be placed before the command, and `--help`/`-h` prints the usage

=== Infrastructure

* Release workflow: run on Node.js 24, whose bundled npm (>= 11.5.1) supports trusted publishing, instead of installing an unpinned `npm@latest` on top of Node.js 22; fail early if npm is too old
* Release workflow: only allow releases from the `main` branch, and never run two releases concurrently
* Test workflow: restrict the `GITHUB_TOKEN` to read-only access
* Release workflow: set the version with `npm version` so `package-lock.json` is updated too (it was stuck at `1.0.0`), and push the release commit and tag only once the package is published, so a failed publish can simply be re-run

== v1.0.2 (2026-08-14)

=== Infrastructure

* Make the GitHub repository public; npm provenance attestations require a public source repository, and publishing with `--provenance` was failing against the previously private repo
* Bump `actions/checkout` and `actions/setup-node` to v7, and test against Node.js 20/22/24 instead of 18/20/22

== v1.0.1 (2026-08-14)

=== Changed

* Publish under the `@bestikk/changelog` npm scope instead of the unscoped `bestikk-changelog` name; the CLI command is still `bestikk-changelog`

=== Infrastructure

* Convert `README.adoc` to `README.md` at publish time (via `downdoc`'s `--prepublish`/`--postpublish` lifecycle scripts), since npmjs.com doesn't render AsciiDoc; `README.adoc` remains the source of truth on GitHub

== v1.0.0 (2026-08-07)

Initial release.

=== Added

* `release` and `notes` library functions and CLI commands to manage a Keep a Changelog (https://keepachangelog.com) style `CHANGELOG.adoc`: roll the `== Unreleased` section into a dated `== v<version> (<date>)` section, and extract a release section as Markdown release notes (via `downdoc`) suitable for a GitHub release
* Support a native Markdown changelog (e.g. `CHANGELOG.md`) as an alternative to AsciiDoc, selected via the `format` option (`adoc`/`markdown`) or auto-detected by the CLI from the `--file` extension
* Make `downdoc` an optional dependency, loaded lazily only when processing the `adoc` format, so a Markdown-only changelog doesn't require it
* Support configurable "Unreleased"/release heading syntax via the `style` option (`keepachangelog`, `title-paren`, `title-paren-suffix`, or a custom style object), covering variations such as asciidoctor-emoji's and asciidoctor-vscode's changelogs.
The `adoc` format shares the same styles, just with the AsciiDoc heading marker instead of Markdown's — both are a "level 2" heading in their respective syntax

=== Infrastructure

* Lint and format the codebase with Biome (`npm run lint`, `npm run lint:fix`, `npm run format`)
* Add a `Test` GitHub Actions workflow running lint and the test suite on Node 18/20/22 for every push and pull request
* Add a `Release` GitHub Actions workflow (manually dispatched with a version) that bumps the package version, rolls the changelog, tags, publishes to npm, and creates the GitHub release using this project's own CLI
