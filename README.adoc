= bestikk-changelog
:uri-repo: https://github.com/bestikk/bestikk-changelog
:uri-keepachangelog: https://keepachangelog.com/en/1.1.0/
:uri-downdoc: https://github.com/asciidoctor/downdoc

{uri-keepachangelog}[Keep a Changelog] for AsciiDoc, with Markdown release notes for GitHub.

Keep your changelog in AsciiDoc (`CHANGELOG.adoc`), and let bestikk-changelog handle the two chores of a release:

* `release`: roll the "Unreleased" section into a dated release section, and start a fresh, empty "Unreleased" section above it;
* `notes`: extract a release section as Markdown release notes, ready to be used as a GitHub release body.

GitHub releases only render Markdown, so the changelog is converted with {uri-downdoc}[downdoc]. The whole document is converted at once, so document attributes (e.g. `+{uri-repo}/issues/42[#42]+`) resolve in the release notes as they do in the changelog.

Markdown changelogs (`CHANGELOG.md`) are supported too, see <<Markdown changelogs>>. This is mostly useful to manage AsciiDoc and Markdown projects with the same tool.

== Quick start

[source,shell]
----
npm install --save-dev @bestikk/changelog

# Roll the "Unreleased" section of CHANGELOG.adoc into "v1.0.0 (<today>)"
npx bestikk-changelog release 1.0.0

# Print the "v1.0.0" section as Markdown release notes
npx bestikk-changelog notes 1.0.0 > release-notes.md
gh release create v1.0.0 --notes-file release-notes.md
----

This project releases itself that way: see its {uri-repo}/blob/main/.github/workflows/release.yml[release workflow].

== AsciiDoc changelog

[source,asciidoc]
----
= Project Changelog
:uri-repo: https://github.com/octocat/hello-world

== Unreleased

== v1.0.0 (2024-01-15)

First stable release.

=== Added

* Export to PDF ({uri-repo}/issues/42[#42])

=== Fixed

* Crash on empty input

== v0.9.0 (2023-12-01)
...
----

* `== Unreleased` collects the changes until the next release.
* `== v<version> (<date>)` is a release section. This is the default heading style (`title-paren`); see <<Heading styles>> for the alternatives.
* An optional paragraph before the first category becomes the release notes summary.
* Category sections (`=== Added`, `=== Fixed`, ...) are free-form, and copied as-is to the release notes.

`notes 1.0.0` outputs:

[source,markdown]
----
## Summary

First stable release.

## Release meta

Released on: 2024-01-15
Released by: octocat
Published by: GitHub

Logs: [full diff](https://github.com/octocat/hello-world/compare/v0.9.0...v1.0.0)

## Changelog

### Added

* Export to PDF ([#42](https://github.com/octocat/hello-world/issues/42))

### Fixed

* Crash on empty input
----

The "Summary" section is omitted when the release has no summary paragraph. The "full diff" link requires both a previous tag and a repository URL, inferred from git when not given (see <<CLI usage>>).

== Markdown changelogs

A Markdown changelog is used as-is, without conversion, and is selected with the `markdown` format. The CLI infers the format from the `--file` extension: `.md`/`.markdown` is `markdown`, anything else is `adoc`.

[source,shell]
----
npx bestikk-changelog release 1.0.0 --file CHANGELOG.md
npx bestikk-changelog notes 1.0.0 --file CHANGELOG.md
----

Its default heading style is the canonical Keep a Changelog syntax (`keepachangelog`):

[source,markdown]
----
# Project Changelog

## [Unreleased]

## [1.0.0] - 2024-01-15

Optional summary paragraph, used as the release notes summary.

### Added

- A new feature

## [0.9.0] - 2023-12-01
...
----

NOTE: Keep a Changelog link reference definitions at the bottom of the file (`[1.0.0]: https://...`) are not updated by `release`, and end up in the release notes of the oldest release.

== Heading styles

The `style` option selects how the "Unreleased" and release headings are spelled. The same presets apply to both formats: an AsciiDoc changelog uses the `==` marker where a Markdown changelog uses `##`.

`title-paren` (default for `adoc`):: e.g. https://github.com/ggrossetie/asciidoctor-emoji/blob/main/CHANGELOG.md[asciidoctor-emoji].
+
[source,text]
----
== Unreleased
== v<version> (<date>)
----

`keepachangelog` (default for `markdown`):: Canonical {uri-keepachangelog}[Keep a Changelog] syntax.
+
[source,text]
----
== [Unreleased]
== [<version>] - <date>
----

`title-paren-suffix`:: e.g. https://github.com/asciidoctor/asciidoctor-vscode/blob/main/CHANGELOG.md[asciidoctor-vscode]. The release heading may also have a "(qualifier)" and a free-form suffix. Both are recognized when reading, but only the suffix is written, via the `suffix` option (e.g. `--suffix "- @octocat"`).
+
[source,text]
----
== Unreleased
== <version> [(qualifier)] (<date>) [suffix]
----

The list of presets is frozen: new conventions won't be added as presets.

For a convention that doesn't fit any preset, the library (not the CLI) also accepts a custom style object. It is an advanced escape hatch: its release heading template and regex must be kept consistent by hand, and its shape may change in a future major version.

[source,js]
----
const style = {
  unreleasedHeading: '## TBD',
  releaseHeadingTemplate: (version, date) => `## Release ${version} — ${date}`,
  releaseHeadingRegex: (escapedVersion) =>
    new RegExp(`(?:^|\\n)## Release ${escapedVersion} — ([^\\n]+)\\n([\\s\\S]*?)(?=\\n## |$)`),
}

rollUnreleased(content, '1.0.0', '2024-01-15', { format: 'markdown', style })
----

The regex always matches against Markdown (an AsciiDoc changelog is converted first), so it uses `##` whatever the format.

== Install

Node.js 20 or later is required.

[source,shell]
----
npm install --save-dev @bestikk/changelog
----

`downdoc`, which converts AsciiDoc to Markdown, is an optional dependency. It is installed by default by `npm`, `npx`, `pnpm` and `yarn`, and only loaded for an AsciiDoc changelog. If it's missing (e.g. installed with `--omit=optional`), processing an AsciiDoc changelog fails with an error telling you to install it.

== CLI usage

[source,text]
----
bestikk-changelog release <version> [--file CHANGELOG.adoc] [--format adoc|markdown]
                                    [--style keepachangelog|title-paren|title-paren-suffix]
                                    [--date YYYY-MM-DD] [--suffix text]
bestikk-changelog notes <version> [--file CHANGELOG.adoc] [--format adoc|markdown]
                                  [--style keepachangelog|title-paren|title-paren-suffix]
                                  [--author name] [--previous-tag tag] [--repo-url url]
                                  [--published-by text]
----

Both commands accept `--file <path>` (default: `CHANGELOG.adoc`), `--format <adoc|markdown>` (default: inferred from `--file`), and `--style <name>` (default: `title-paren` for `adoc`, `keepachangelog` for `markdown`).

`release` accepts `--date <YYYY-MM-DD>` (default: today) and `--suffix <text>` (appended to the release heading by the `title-paren-suffix` style).

`notes` accepts:

* `--author <name>`: defaults to `$GITHUB_ACTOR`, or the author of the `v<version>` tag's commit;
* `--previous-tag <tag>`: defaults to the tag before `v<version>`;
* `--repo-url <url>`: defaults to the GitHub URL of the `origin` git remote;
* `--published-by <text>`: the "Published by" line of the release notes, defaults to `GitHub`; an empty value (`--published-by=`) omits the line.

The previous tag and the repository URL are used to link the full diff between releases.

Options can be written as `--option value` or `--option=value`, anywhere on the command line. `--help` (`-h`) prints the usage.

The CLI exits with `0` on success, and with `9` on invalid usage (unknown command or option, missing argument or option value), after printing the usage. Any other error (e.g. changelog file or section not found) is reported as a one-line message on stderr, with exit code `1`.

== Library usage

[source,js]
----
import { rollUnreleased, extractReleaseNotes } from '@bestikk/changelog'
import { readFileSync, writeFileSync } from 'node:fs'

const content = readFileSync('CHANGELOG.adoc', 'utf8')

// Roll "Unreleased" into "v1.0.0 (2024-01-15)" (the format defaults to "adoc")
writeFileSync('CHANGELOG.adoc', rollUnreleased(content, '1.0.0', '2024-01-15'))

// Extract "v1.0.0" as Markdown release notes
const notes = await extractReleaseNotes(content, '1.0.0', {
  author: 'octocat',
  previousTag: 'v0.9.0',
  repoUrl: 'https://github.com/octocat/hello-world',
})
----

Both functions take an optional last argument with `format` (`adoc` or `markdown`), `style` (a preset name or a custom style object), and, for `rollUnreleased`, `suffix`. `extractReleaseNotes` also accepts `publishedBy` (defaults to `'GitHub'`; an empty string or `null` omits the "Published by" line).

== Behavior notes

* The version can be given with or without a leading `v` (`v1.0.0` is the same as `1.0.0`). Release headings are written as the style dictates, and the git tag is always `v<version>`.
* `release` refuses to roll the "Unreleased" section into a version that already has a release section, whatever its date (or suffix).
* CRLF line endings are supported: `release` writes them back as-is, and `notes` always outputs LF.
* A `##`/`###` line inside a fenced code block (including AsciiDoc source and literal blocks, converted to fenced code blocks by downdoc) is never mistaken for a release or category heading.
